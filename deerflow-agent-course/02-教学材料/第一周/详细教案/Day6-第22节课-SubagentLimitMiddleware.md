# 🎓 详细教案 - SubagentLimitMiddleware（子代理限制中间件）

## 📋 课程基本信息
- **课程名称**: SubagentLimitMiddleware（子代理限制中间件）
- **授课日期**: 第6天 - 第2节课
- **上课时间**: 10:00-10:45（45分钟）
- **授课教师**: 张老师（高级架构师讲师）
- **学生背景**: 已完成ViewImageMiddleware学习，了解中间件基础概念
- **教室环境**: 虚拟教室，共享屏幕，10名学员在线

## 🎯 教学目标

### 知识目标（学生将知道/理解）
1. 理解多Agent系统中子代理资源管理的重要性和挑战
2. 掌握子代理限制的四种核心维度：深度、并发、时间、资源
3. 理解SubagentLimitMiddleware的设计原理和执行流程
4. 了解防止Agent系统资源滥用的安全策略和最佳实践

### 技能目标（学生将能够）
1. 配置子代理限制策略（YAML配置文件）
2. 实现子代理深度限制和并发控制逻辑
3. 编写子代理状态跟踪和管理机制
4. 设计自定义的异常类型和处理流程

### 情感/态度目标
1. 培养系统安全性和稳定性的责任意识
2. 建立资源优化和性能调优的工程思维
3. 激发对分布式系统资源管理的研究兴趣

## 📚 教学重点与难点
- **教学重点**: 
  1. 子代理限制的四种维度及其实现原理
  2. SubagentLimitMiddleware的before/after执行流程
  3. 并发控制和状态跟踪机制
- **教学难点**: 
  1. 嵌套深度计算和传递逻辑
  2. 并发计数器的线程安全实现
  3. 资源限制的动态调整策略
- **突破方法**: 
  1. 通过流程图讲解嵌套深度传递机制
  2. 使用简化版代码示例演示并发控制
  3. 提供配置模板和调试方法

# 课堂练习：实现子代理并发计数器

## 任务描述
在提供的SubagentLimitMiddleware类基础上，完善并发控制逻辑：
1. 跟踪当前运行中的子代理状态
2. 在before_agent中检查并发数量是否超限
3. 在after_agent中更新子代理完成状态
4. 实现线程安全的计数器操作

## 要求
- [ ] 使用字典跟踪子代理状态（running/completed）
- [ ] 准确计算当前运行中的子代理数量
- [ ] 当并发数超限时抛出MaxConcurrentExceededError
- [ ] 确保线程安全（考虑多线程环境）

## 步骤指导
1. 在__init__中初始化active_subagents字典
2. 在before_agent中：检查活跃子代理数量 → 如果超限抛出异常 → 注册新子代理
3. 在after_agent中：根据agent_id找到对应子代理 → 更新状态为completed → 记录结束时间
4. 实现辅助方法：获取当前运行中子代理数量

## 提示与技巧
- 使用agent_id作为字典键，便于查找和更新
- 状态字段建议："status": "running" 或 "status": "completed"
- 考虑使用threading.Lock或asyncio.Lock保证线程安全
- 可以添加定时清理已完成子代理的机制

## 检查点
- [ ] 测试1：正常创建5个子代理（max_concurrent=5）不报错
- [ ] 测试2：创建第6个子代理抛出MaxConcurrentExceededError  
- [ ] 测试3：子代理完成后，计数器正确减少
- [ ] 测试4：多线程环境下并发操作不出现竞态条件

## 扩展挑战（可选）
- 添加子代理超时自动清理机制
- 实现基于权重的并发控制（不同Agent占用不同权重）
- 添加监控指标导出（Prometheus metrics）
