# 🎓 详细教案 - 实战：图片处理和任务管理

## 📋 课程基本信息
- **课程名称**: 实战：图片处理和任务管理
- **授课日期**: 第6天 - 第4节课
- **上课时间**: 12:00-12:45（45分钟）
- **授课教师**: 张老师（高级架构师讲师）
- **学生背景**: 已完成Day6前3节课学习，掌握三个中间件的独立使用
- **教室环境**: 虚拟教室，共享屏幕，10名学员在线

## 🎯 教学目标

### 知识目标（学生将知道/理解）
1. 理解多中间件协同工作的设计模式和执行流程
2. 掌握图片分析流水线的完整架构和组件交互
3. 理解任务分解、执行、跟踪、聚合的全流程管理
4. 了解中间件链的正确顺序和依赖关系设计

### 技能目标（学生将能够）
1. 集成ViewImageMiddleware、TodoMiddleware、SubagentLimitMiddleware
2. 设计完整的图片分析流水线架构
3. 实现主任务和子任务的创建、依赖管理
4. 编写集成测试验证多中间件协同工作

### 情感/态度目标
1. 培养系统集成和架构设计的综合能力
2. 建立从模块开发到系统集成的工程思维
3. 激发对复杂系统设计和实现的挑战精神

## 📚 教学重点与难点
- **教学重点**: 
  1. 多中间件集成架构设计
  2. 图片分析流水线完整实现
  3. 任务依赖关系和工作分解结构
- **教学难点**: 
  1. 中间件执行顺序设计和依赖管理
  2. 主任务与子任务的协调机制
  3. 异步处理和数据流传递
- **突破方法**: 
  1. 通过流程图展示中间件执行顺序
  2. 分步骤实现流水线各阶段
  3. 提供完整的集成测试用例

## 🎭 师生互动设计

### 提问策略
1. **导入提问**: "你设计过最复杂的系统集成是什么？"（激活经验）
2. **引导提问**: "中间件执行顺序为什么重要？错误顺序会导致什么？"（引导技术思考）

## 🔧 差异化教学

1. **简化任务**: 提供ImageAnalysisPipeline框架代码，只需填空实现关键部分

4. **成功体验**: 设计可达成的子目标：实现单一图片分析功能

### 针对进阶学生
1. **扩展挑战**: 实现支持并行子任务执行的增强版流水线
2. **创新空间**: 鼓励探索基于事件驱动的流水线架构
3. **领导机会**: 担任小组长，帮助其他同学理解异步协调
4. **项目实战**: 将图片分析流水线集成到实际业务系统中

### 针对中等水平学生
1. **渐进提升**: 从串行执行扩展到有限并行执行
2. **榜样学习**: 学习优秀同学的错误处理和回滚设计
3. **目标引导**: 设定明确目标：实现完整的图片分析系统
4. **反馈激励**: 及时肯定架构优化和性能改进

## 📊 评估方式

### 形成性评估（课堂内）
1. **观察评估**: 观察学生设计流水线架构的熟练程度
2. **提问评估**: 通过提问检验中间件集成知识掌握
3. **练习评估**: 检查任务创建和依赖管理实现正确性
4. **自评互评**: 学生自我评估架构质量，互相评估实现效果

### 总结性评估（课堂后）
1. **作业评估**: 批改图片分析流水线实现，评分反馈
2. **测验评估**: 单元测验，检验系统集成知识掌握
3. **项目评估**: 在周项目中评估流水线模块质量
4. **综合评估**: 结合课堂表现、作业、测验综合评分

### 评估标准
- **优秀（90-100分）**: 实现完整功能，架构优雅，支持扩展，性能优化，有创新点
- **良好（80-89分）**: 实现基本功能，代码清晰，通过所有测试
- **合格（60-79分）**: 实现核心功能，需要少量调试才能运行
- **需改进（<60分）**: 无法实现基本功能，需要重新学习核心概念

## 🚨 应急预案

### 技术故障
1. **网络中断**: 准备离线演示材料，包含完整的代码示例
2. **软件故障**: 准备在线Python环境（Google Colab备用）
3. **API密钥问题**: 准备模拟视觉模型返回固定描述
4. **图片加载失败**: 准备Base64编码的测试图片字符串

### 学生问题
1. **理解困难**: 放慢流水线架构讲解节奏，增加数据流图示例
2. **设备问题**: 提供远程协助，共享屏幕指导环境配置
3. **时间不足**: 调整内容优先级，先确保核心流水线实现
4. **兴趣不足**: 展示智能图片分析的实际应用案例，强调商业价值

### 内容调整
1. **进度过快**: 增加中间件集成练习时间，补充设计模式讲解
2. **进度过慢**: 精简并行处理部分，聚焦串行流水线实现
3. **内容过难**: 分解ImageAnalysisPipeline实现，分步骤教学
4. **内容过易**: 增加分布式任务调度、容错处理等扩展内容

### 附录B：学生练习任务卡
```markdown
# 课堂练习：实现图片分析流水线任务创建

## 任务描述
在提供的ImageAnalysisPipeline类基础上，完善analyze_image方法中的任务创建逻辑：
1. 创建主分析任务（main_analysis）
2. 根据analysis_types创建对应的子任务
3. 建立正确的依赖关系（子任务依赖主任务）
4. 设置合理的优先级和预估时间

## 要求
- [ ] 主任务：id="main_analysis"，优先级最高（1），依赖为空
- [ ] 子任务：id="subtask_{i}"，依赖包含"main_analysis"
- [ ] 合理设置预估时间：主任务60秒，子任务各30秒
- [ ] 使用datetime.now()设置创建和更新时间

## 步骤指导
1. 导入必要模块：datetime, uuid
2. 创建主任务TodoItem对象，设置基本属性
3. 遍历analysis_types列表，为每种分析类型创建子任务
4. 设置子任务的dependencies字段包含"main_analysis"
5. 将所有任务添加到todos列表中
6. 构建请求字典，包含thread_id、messages、todos等字段

## 提示与技巧
- 使用uuid生成唯一thread_id：f"image_analysis_{uuid.uuid4().hex[:8]}"
- 主任务状态设为"in_progress"，子任务设为"pending"
- 合理设置priority：主任务1（最高），子任务2
- 使用列表推导式简化子任务创建：sub_todos = [TodoItem(...) for i, at in enumerate(analysis_types)]

## 检查点
- [ ] 测试1：单分析类型创建1主任务+1子任务
- [ ] 测试2：多分析类型创建1主任务+N子任务  
- [ ] 测试3：子任务正确依赖主任务（dependencies包含"main_analysis"）
- [ ] 测试4：请求字典包含所有必要字段

## 扩展挑战（可选）
- 添加任务预估时间基于分析类型动态计算
- 实现任务优先级基于分析复杂度动态调整
- 添加任务标签（tags）字段，支持分类管理
```
