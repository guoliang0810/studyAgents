## 📚 基础知识回顾

### 1. 配置系统设计哲学
- **约定优于配置**：提供合理的默认值，减少用户配置工作量
- **分层覆盖原则**：配置源按优先级分层，高优先级覆盖低优先级
- **配置即代码**：配置和代码一样进行版本控制、测试和审查
- **环境分离**：不同环境（开发、测试、生产）使用独立配置

### 2. 配置加载顺序（优先级从低到高）
1. **默认配置**：代码中定义的默认值，最低优先级
2. **文件配置**：YAML/JSON配置文件，支持结构化配置
3. **环境变量**：操作系统环境变量，便于容器化部署
4. **命令行参数**：运行时临时覆盖，最高优先级
5. **运行时配置**：程序运行时的动态配置

### 3. 深度合并算法
- **字典合并**：递归合并嵌套字典，相同键时覆盖或合并
- **数组合并策略**：替换、追加、扩展、去重、交集
- **类型感知**：根据数据类型选择合并策略
- **性能考虑**：避免深度复制，优化递归性能

### 4. 配置验证技术
- **必需字段验证**：确保关键配置项存在
- **类型验证**：验证配置值类型是否符合预期
- **值范围验证**：数值范围、字符串长度、正则表达式匹配
- **依赖验证**：配置项间的依赖关系检查
- **自定义验证**：业务规则验证

### 5. 配置模板渲染
- **变量替换**：`${VAR_NAME}` 和 `${VAR_NAME:default}`
- **环境变量集成**：自动从环境变量读取配置值
- **函数调用**：支持自定义函数处理配置值
- **类型转换**：自动转换字符串到适当类型
- **条件表达式**：支持简单条件逻辑

## 🛠️ 练习任务

### 任务1：实现增强版ConfigLoader

#### 1.1 扩展配置源支持
**要求**：
- 在现有ConfigLoader基础上，添加JSON配置文件和INI配置文件支持
- 支持远程配置源（HTTP API），能够从远程服务拉取配置
- 实现配置源健康检查和故障切换机制
- 支持配置源权重和动态优先级调整

**提示**：
- JSON配置文件：使用`json`模块加载，支持嵌套结构
- INI配置文件：使用`configparser`模块，适合扁平配置
- 远程配置源：使用`requests`库，支持重试和超时
- 健康检查：定期检查配置源可用性，故障时自动切换到备用源
- 权重管理：根据配置源可靠性动态调整权重

#### 1.2 优化深度合并算法
**要求**：
- 实现更高效的数据合并算法，减少内存分配和复制
- 支持自定义合并策略：不同配置路径使用不同合并策略
- 实现合并冲突检测和解决机制
- 添加合并性能监控和优化建议

**提示**：
- 内存优化：使用视图或浅拷贝减少内存分配
- 策略注解：通过注解或元数据指定合并策略
- 冲突检测：检测配置冲突，提供解决建议（保留、覆盖、合并）
- 性能监控：记录合并耗时，识别性能瓶颈

#### 1.3 增强错误处理和恢复
**要求**：
- 实现详细的配置加载错误报告，包含错误上下文和修复建议
- 支持配置加载失败时的降级策略和优雅恢复
- 实现配置加载重试机制和回退策略
- 添加配置加载审计日志，记录所有配置操作

**提示**：
- 错误报告：结构化错误信息，包含错误类型、位置、原因、建议
- 降级策略：主配置源失败时降级到备用源或本地缓存
- 重试机制：指数退避重试，避免雪崩效应
- 审计日志：记录配置加载时间、来源、操作者、结果
