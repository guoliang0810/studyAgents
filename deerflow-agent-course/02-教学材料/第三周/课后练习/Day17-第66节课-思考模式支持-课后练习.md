## 📝 练习任务

### 任务1：思考模式配置和任务特征数据类（40分钟）

**目标**：设计思考模式配置数据类和任务特征数据类。

**要求**：
1. 创建`thinking_config.py`文件，实现以下内容：
   - `ThinkingMode`枚举：定义FAST、BALANCED、DEEP、CREATIVE四种思考模式
   - `ReasoningDepth`枚举：定义SHALLOW、MEDIUM、DEEP三种推理深度
   - `ThinkingConfig`数据类：包含思考模式配置字典
   - 实现以下方法：
     - `from_yaml()`：从YAML内容创建配置对象
     - `from_file()`：从YAML文件创建配置对象
     - `validate()`：验证配置有效性，返回错误列表
     - `get_mode_config()`：获取指定模式的配置
     - `add_mode()`：添加新的思考模式
     - `remove_mode()`：移除思考模式
     - `to_yaml()`：将配置转换为YAML格式
     - `to_dict()`：将配置转换为字典

2. 创建`task_features.py`文件，实现以下内容：
   - `TaskType`枚举：定义CODE_GENERATION、DEBUGGING、CREATIVE_WRITING、DATA_ANALYSIS、QUICK_ANSWER、RESEARCH、PLANNING、TRANSLATION、SUMMARIZATION等任务类型
   - `TaskFeatures`数据类：包含任务类型、复杂度评分、紧急程度评分、领域、约束条件等字段
   - 实现`validate()`方法：验证任务特征有效性

3. 设计要求：
   - 使用Python 3.12+的新特性（如enum.StrEnum）
   - 为所有字段和方法添加完整的类型提示
   - 实现严格的参数验证（如复杂度、紧急度范围检查）
   - 支持中文和英文注释，文档字符串符合Google风格

**提示**：
- 思考模式配置应包含temperature、max_tokens、reasoning_depth等核心参数
- 验证方法应检查参数范围、必需参数、类型正确性
- YAML解析应考虑不同的文件结构兼容性

**检查点**：
- [ ] ThinkingConfig类支持完整的YAML配置管理
- [ ] TaskFeatures类包含所有必要的任务特征字段
- [ ] 所有验证方法正确实现参数范围检查
- [ ] 枚举定义完整，包含所有必要的思考模式和任务类型
- [ ] 代码符合PEP 8规范，注释清晰

### 任务2：智能思考模式选择器实现（50分钟）

**目标**：实现智能的思考模式选择器，基于多规则决策逻辑。

**要求**：
1. 创建`thinking_mode_selector.py`文件，实现`ThinkingModeSelector`类：
   - 初始化方法：接收ThinkingConfig对象，初始化默认规则
   - 核心方法：
     - `select_mode()`：根据任务特征选择思考模式
     - `select_mode_with_confidence()`：选择模式并返回置信度
     - `explain_selection()`：解释选择过程，返回详细决策信息
     - `add_custom_rule()`：添加自定义选择规则
     - `add_type_mapping()`：添加或更新任务类型映射
     - `get_available_modes()`：获取所有可用思考模式
     - `get_mode_description()`：获取模式描述

2. 实现多规则决策逻辑：
   - **规则优先级**：
     1. 自定义规则（最高优先级）
     2. 紧急度规则（urgency > 0.8时强制快速模式）
     3. 任务类型映射规则
     4. 复杂度规则（complexity > 0.7用深度模式，>0.3用平衡模式，否则用快速模式）
   - **置信度计算**：基于规则匹配程度计算0.0-1.0的置信度
   - **选择解释**：记录所有应用的规则和决策过程

3. 实现默认任务类型映射：
   - CODE_GENERATION → BALANCED
   - DEBUGGING → DEEP
   - CREATIVE_WRITING → CREATIVE
   - DATA_ANALYSIS → BALANCED
   - QUICK_ANSWER → FAST
   - RESEARCH → DEEP
   - PLANNING → DEEP
   - TRANSLATION → BALANCED
   - SUMMARIZATION → FAST

**提示**：
- 使用策略模式或责任链模式实现规则优先级
- 置信度计算应考虑规则冲突和匹配程度
- 选择解释应提供足够的信息用于调试和优化

**检查点**：
- [ ] ThinkingModeSelector类正确实现所有核心方法
- [ ] 多规则决策逻辑正确实现，优先级处理正确
- [ ] 置信度计算合理，考虑多种因素
- [ ] 选择解释功能完整，提供详细决策信息
- [ ] 自定义规则系统灵活可扩展

### 任务3：思考模式应用器和缓存机制（45分钟）

**目标**：实现思考模式应用器，将配置应用到模型调用，并实现缓存机制。

**要求**：
1. 创建`thinking_mode_applicator.py`文件，实现`ThinkingModeApplicator`类：
   - 初始化方法：接收ThinkingConfig对象，初始化缓存和统计
   - 核心方法：
     - `apply_to_model_call()`：同步应用思考模式到模型调用
     - `apply_to_model_call_async()`：异步应用思考模式到模型调用
     - `get_performance_stats()`：获取性能统计信息
     - `clear_cache()`：清空缓存
     - `reset_stats()`：重置性能统计

2. 实现模式应用功能：
   - 参数提取：从模式配置提取temperature、max_tokens等参数
   - 缓存管理：基于模式配置、提示和参数生成缓存键
   - 特殊特性支持：
     - 反思迭代：如果模式配置allow_reflection为true，执行多次迭代
     - 缓存控制：如果use_cache为true，启用结果缓存
   - 性能统计：跟踪调用次数、成功率、响应时间、缓存命中率

3. 实现缓存键生成：
   - 基于模式名称、提示内容和调用参数生成唯一键
   - 使用哈希算法（如SHA256）生成固定长度键
   - 考虑参数顺序和类型一致性

4. 实现性能统计：
   - 按思考模式统计调用次数、成功次数、失败次数
   - 计算平均响应时间、成功率、缓存命中率
   - 提供统计重置和导出功能

**提示**：
- 使用字典或LRU缓存实现内存缓存
- 反思迭代可以通过递归调用模型实现
- 异步方法应正确处理异步模型函数
- 性能统计应考虑线程安全和并发访问

**检查点**：
- [ ] ThinkingModeApplicator类正确实现所有核心方法
- [ ] 缓存机制正确工作，缓存键生成唯一且高效
- [ ] 反思迭代功能正确实现，支持多次迭代
- [ ] 性能统计完整准确，包含所有重要指标
- [ ] 同步和异步方法都正确实现，支持各种模型函数
