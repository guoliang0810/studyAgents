## 📝 练习任务

### 任务1：视觉模型配置和图像处理器基类（40分钟）

**目标**：设计视觉模型配置数据类和图像处理器基类。

**要求**：
1. 创建`vision_config.py`文件，实现以下内容：
   - `VisionModelConfig`数据类：包含模型提供商、模型名称、能力列表、视觉配置等字段
   - `VisionConfig`数据类：包含视觉模型配置字典
   - 实现以下方法：
     - `from_yaml()`：从YAML内容创建配置对象
     - `from_file()`：从YAML文件创建配置对象
     - `validate()`：验证配置有效性，返回错误列表
     - `get_model_config()`：获取指定模型的配置
     - `add_model()`：添加新的视觉模型配置
     - `remove_model()`：移除视觉模型配置
     - `to_yaml()`：将配置转换为YAML格式
     - `to_dict()`：将配置转换为字典
     - `can_handle_image()`：检查模型能否处理特定图像
     - `get_max_images_per_request()`：获取请求限制

2. 创建`image_processor.py`文件，实现以下内容：
   - `ImageProcessor`抽象基类：定义图像处理器的接口
   - `ImageInfo`数据类：存储图像数据和元数据
   - `ProcessedImage`数据类：存储处理后的图像信息
   - 辅助函数：`parse_size()`用于解析大小字符串（如"20MB"→字节数）

3. 设计要求：
   - 使用Python 3.12+的新特性（如enum.StrEnum）
   - 为所有字段和方法添加完整的类型提示
   - 实现严格的参数验证（如大小限制、格式支持）
   - 支持中文和英文注释，文档字符串符合Google风格
   - 异步支持：所有处理方法都应该是异步的

**提示**：
- 视觉模型配置应包含max_image_size、supported_formats、max_images_per_request等核心参数
- 验证方法应检查参数范围、必需参数、类型正确性
- YAML解析应考虑不同的文件结构兼容性
- 图像处理器基类应定义抽象方法`process()`

**检查点**：
- [ ] VisionModelConfig类支持完整的视觉模型配置
- [ ] VisionConfig类支持YAML配置管理和验证
- [ ] ImageProcessor基类定义清晰，支持异步处理
- [ ] 辅助函数正确实现大小字符串解析
- [ ] 所有验证方法正确实现参数范围检查
- [ ] 代码符合PEP 8规范，注释清晰

### 任务2：图像处理器具体实现（50分钟）

**目标**：实现多种图像处理器的具体实现。

**要求**：
1. 在`image_processor.py`文件中，实现以下图像处理器类：
   - `FormatConverter`：图像格式转换器
     - 支持PNG、JPEG、GIF、WebP格式转换
     - 支持质量参数控制（JPEG质量85%）
     - 支持无损和有损转换
   - `SizeResizer`：图像大小调整器
     - 支持按最大尺寸限制调整
     - 支持渐进式优化（质量→尺寸）
     - 保持宽高比，智能缩放
   - `QualityOptimizer`：图像质量优化器
     - 支持锐化、对比度调整
     - 支持渐进式质量降低（85%→70%→50%→30%）
     - 优化视觉效果同时减少文件大小
   - `MetadataStripper`：图像元数据清理器
     - 清除EXIF、GPS等隐私数据
     - 只保留像素数据
     - 支持自定义清理策略

2. 每个处理器类必须：
   - 继承`ImageProcessor`抽象基类
   - 实现`process()`异步方法
   - 实现`__str__()`方法返回处理器描述
   - 支持配置参数（如目标格式、最大尺寸、质量级别）
   - 正确处理异常和边界情况

3. 实现处理器工厂：
   - `ProcessorFactory`类：根据配置创建处理器实例
   - 支持从YAML配置创建处理器链
   - 支持动态添加和移除处理器

**提示**：
- 使用Pillow库进行图像处理操作
- 注意内存管理：处理大图像时使用流式处理
- 异步方法应正确处理I/O操作
- 处理器配置应考虑灵活性和可扩展性

**检查点**：
- [ ] FormatConverter正确实现格式转换，支持多种格式
- [ ] SizeResizer正确实现大小调整，支持渐进优化
- [ ] QualityOptimizer正确实现质量优化，支持渐进降低
- [ ] MetadataStripper正确实现元数据清理，保护隐私
- [ ] ProcessorFactory正确创建和管理处理器实例
- [ ] 所有处理器正确处理异常和边界情况

### 任务3：视觉处理管道实现（45分钟）

**目标**：实现视觉处理管道，协调多个图像处理器。

**要求**：
1. 创建`vision_pipeline.py`文件，实现`VisionPipeline`类：
   - 初始化方法：接收VisionConfig对象，初始化处理器链
   - 核心方法：
     - `process_image()`：异步处理单个图像
     - `process_batch()`：异步批量处理多个图像
     - `prepare_images_for_model()`：为特定模型准备图像
     - `add_processor()`：添加处理器到处理链
     - `remove_processor()`：从处理链移除处理器
     - `get_processor_stats()`：获取处理器统计信息
     - `reset_stats()`：重置统计信息

2. 实现管道功能：
   - **责任链模式**：处理器按配置顺序执行
   - **异步流水线**：支持并发图像处理
   - **错误隔离**：单个图像失败不影响其他处理
   - **性能统计**：跟踪处理时间、成功率、压缩效果
   - **缓存机制**：支持处理结果缓存

3. 实现智能处理策略：
   - **模型适配**：根据目标模型调整处理参数
   - **渐进优化**：逐步降低质量/尺寸直到满足限制
   - **格式选择**：选择模型支持的最佳格式
   - **安全处理**：自动应用元数据清理

4. 实现性能统计：
   - 按处理器统计处理次数、成功次数、失败次数
   - 计算平均处理时间、压缩比例、大小减少百分比
   - 提供统计重置和导出功能

**提示**：
- 使用asyncio实现异步并发处理
- 处理器链应支持动态调整顺序
- 缓存键应基于图像内容、处理器配置和目标模型
- 性能统计应考虑线程安全和并发访问

**检查点**：
- [ ] VisionPipeline类正确实现所有核心方法
- [ ] 责任链模式正确实现，处理器按顺序执行
- [ ] 异步批量处理正确工作，支持高并发
- [ ] 智能处理策略正确实现，满足模型限制
- [ ] 性能统计完整准确，包含所有重要指标
- [ ] 错误隔离机制正确工作，单个失败不影响整体
