### 任务1：模型定义和配置数据类（40分钟）

**目标**：设计模型能力定义数据类和路由器配置数据类。

**要求**：
1. 创建`model_definitions.py`文件，实现以下内容：
   - `ModelCapabilities`数据类：定义模型支持的能力，包括：
     - `supports_vision`: bool - 是否支持视觉处理
     - `supports_function_calling`: bool - 是否支持函数调用
     - `supports_long_context`: bool - 是否支持长上下文
     - `max_context_length`: int - 最大上下文长度
     - `reasoning_depth`: str - 推理深度（shallow/medium/deep）
   - 实现`has_capability()`方法：检查是否支持特定能力
   - `ModelConfig`数据类：存储模型配置，包括：
     - `provider`: str - 模型提供者
     - `model_name`: str - 模型名称
     - `capabilities`: ModelCapabilities - 模型能力
     - `cost_per_token`: float - 每token成本
     - `config`: Dict[str, Any] - 其他配置参数
   - 实现`__post_init__()`方法验证配置

2. 创建`router_config.py`文件，实现以下内容：
   - `RoutingDecision`数据类：路由决策结果，包括：
     - `model_name`: str - 选择的模型名称
     - `strategy`: str - 使用的策略名称
     - `confidence`: float - 选择置信度（0-1）
     - `reason`: str - 选择理由
     - `metadata`: Dict[str, Any] - 元数据
   - 实现`to_dict()`和`__str__()`方法
   - `RouterConfig`数据类：路由器配置，包括：
     - `model_config`: Dict - 模型配置字典
     - `default_model`: str - 默认模型名称
     - `task_routing`: Dict[str, List[str]] - 任务类型到模型列表的映射
     - `models`: Dict[str, ModelConfig] - 模型配置字典
   - 实现以下方法：
     - `from_yaml()`: 从YAML内容创建配置对象
     - `from_file()`: 从YAML文件创建配置对象
     - `to_yaml()`: 将配置转换为YAML格式
     - `to_dict()`: 将配置转换为字典
   - `TaskFeatures`数据类：任务特征，包括：
     - `task_type`: Optional[str] - 任务类型
     - `complexity`: float - 复杂度评分（0-1）
     - `urgency`: float - 紧急程度评分（0-1）
     - `budget`: Optional[float] - 预算限制
     - `latency_requirement`: Optional[float] - 延迟要求（秒）
     - `required_capabilities`: List[str] - 所需能力列表
   - 实现`validate()`方法验证任务特征

3. 设计要求：
   - 使用Python 3.12+的新特性（如dataclass参数）
   - 为所有字段和方法添加完整的类型提示

### 任务2：使用情况跟踪器和性能统计（30分钟）

**目标**：实现使用情况跟踪器，记录模型使用情况和计算性能得分。

**要求**：
1. 创建`usage_tracker.py`文件，实现以下内容：
   - `UsageTracker`类：跟踪模型使用情况和性能统计
   - 内部数据结构：
     - `usage_stats`: Dict[str, Dict] - 使用统计字典
     - `performance_scores`: Dict[str, float] - 性能得分缓存
   - 实现以下方法：
     - `record_usage()`: 记录模型使用情况，包括：
       - `model_name`: str - 模型名称
       - `tokens_used`: int - 使用的token数（可选）
       - `success`: bool - 是否成功
       - `response_time`: float - 响应时间（秒）
     - `get_performance_score()`: 获取模型性能得分，逻辑：
       - 如果已有缓存得分，直接返回
       - 否则基于历史数据计算：
         - 成功率 = 成功次数 / 总调用次数
         - 响应时间得分 = max(0, 1 - min(平均响应时间, 5) / 5)
         - 综合得分 = 成功率 × 0.6 + 响应时间得分 × 0.4
       - 如果没有历史数据，返回默认值（gpt-4: 0.9, gpt-3.5-turbo: 0.7等）
     - `get_usage_summary()`: 获取使用情况摘要，包括：
       - 调用次数、成功率、平均token数、平均响应时间、最后使用时间
     - `_update_performance_score()`: 更新性能得分缓存

2. 设计要求：
   - 支持线程安全（可选加分项）
   - 实现合理的缓存策略，避免重复计算
   - 考虑性能优化，如批量更新

**提示**：
- 使用defaultdict简化统计管理
- 性能得分计算应考虑数据不足的情况
- 响应时间得分需要归一化处理

**检查点**：
- [ ] UsageTracker正确记录模型使用情况
- [ ] 性能得分计算逻辑正确实现
- [ ] 使用情况摘要包含所有必要统计信息
- [ ] 缓存机制有效避免重复计算
- [ ] 默认得分处理逻辑合理

### 任务3：路由策略设计和实现（50分钟）

**目标**：设计路由策略基类，并实现多种具体路由策略。

**要求**：
1. 创建`routing_strategies.py`文件，实现以下内容：
   - `RoutingStrategy`抽象基类：
     - 抽象方法`async def route(prompt: str, context: Dict[str, Any]) -> RoutingDecision`
     - 方法`get_strategy_name()`返回策略名称
   - `CostOptimizedStrategy`成本优化策略：
     - 选择成本最低的可用模型
     - 置信度固定为0.8
     - 理由为"选择成本最低的模型"
   - `PerformanceOptimizedStrategy`性能优化策略：
     - 构造函数接收`UsageTracker`实例
     - 选择性能得分最高的可用模型
     - 置信度为模型性能得分
     - 理由包含性能得分信息
   - `BalancedStrategy`平衡策略：
     - 构造函数接收`UsageTracker`实例
     - 综合计算成本得分和性能得分：
       - 成本得分 = 1 - min(成本 × 1000, 1.0)
       - 性能得分 = 使用跟踪器获取的性能得分
       - 综合得分 = 成本得分 × 0.4 + 性能得分 × 0.6
     - 选择综合得分最高的模型
     - 置信度为综合得分
     - 理由包含成本和性能信息
   - `LearningBasedStrategy`学习型策略：
     - 内部维护使用历史列表
     - 基于历史成功率选择模型
     - 实现`record_result()`方法记录使用结果
     - 选择历史成功率最高的模型
     - 置信度为成功率
     - 理由包含成功率信息

2. 设计要求：
   - 所有策略实现完整的异步接口
   - 考虑上下文信息的完整性和可用性
   - 错误处理：当没有可用模型时抛出合适异常
   - 策略名称应清晰反映策略类型

**提示**：
- 上下文应包含`available_models`列表
- 成本得分计算需要归一化处理
- 学习型策略需要考虑历史数据不足的情况

**检查点**：
- [ ] RoutingStrategy基类正确定义抽象接口
- [ ] 所有具体策略正确实现路由逻辑
- [ ] 成本优化策略正确选择最低成本模型
- [ ] 性能优化策略正确使用性能得分
- [ ] 平衡策略正确计算综合得分
- [ ] 学习型策略正确记录历史和使用成功率
- [ ] 所有策略提供合适的置信度和理由

### 任务4：模型路由器实现（40分钟）

**目标**：实现基础模型路由器，支持候选模型筛选和多维度评分。

**要求**：
1. 创建`model_router.py`文件，实现以下内容：
   - `ModelRouter`类：基础模型路由器
   - 构造函数接收`RouterConfig`配置
   - 内部组件：
     - `config`: RouterConfig - 路由器配置
     - `usage_tracker`: UsageTracker - 使用情况跟踪器
     - `model_registry`: Dict[str, Any] - 模型实例注册表
   - 实现以下方法：
     - `register_model()`: 注册模型实例到注册表
     - `async def route()`: 路由到合适的模型，参数：
       - `prompt`: str - 用户提示
       - `task_type`: str - 任务类型（可选）
       - `budget`: float - 预算限制（可选）
       - `latency_requirement`: float - 延迟要求（可选）
     - 路由逻辑流程：
       1. 获取候选模型列表（基于任务类型）
       2. 过滤模型（基于预算和延迟要求）
       3. 如果没有候选模型，回退到默认模型
       4. 选择最佳模型（基于多维度评分）
       5. 记录使用情况
       6. 返回模型实例
     - `_get_candidate_models()`: 获取候选模型列表
       - 如果指定任务类型，使用task_routing映射
       - 否则返回所有模型
     - `_filter_models()`: 过滤模型
       - 基于预算过滤：成本超过预算/1000的模型
       - 可扩展：添加延迟要求等其他过滤条件
     - `_select_best_model()`: 选择最佳模型
       - 多维度评分：性能得分40%、成本得分30%、适合度得分30%
       - 性能得分：使用UsageTracker获取
       - 成本得分：1 - min(成本 × 1000, 1.0)
       - 适合度得分：基于提示长度和复杂度计算
     - `_calculate_fit_score()`: 计算模型适合度得分
       - 考虑提示长度：长提示适合长上下文模型
       - 考虑复杂度：复杂任务适合深度推理模型
       - 简单启发式实现即可
     - `get_usage_stats()`: 获取使用统计

2. 设计要求：
   - 路由方法支持完整的异步调用
   - 评分权重可配置（加分项）
   - 错误处理：默认模型未注册时抛出异常
   - 支持模型实例的动态注册和管理

**提示**：
- 候选模型筛选应考虑任务类型映射
- 过滤逻辑应支持多种条件组合
- 适合度得分计算可以基于简单规则

**检查点**：
- [ ] ModelRouter正确实现完整路由流程

- [ ] 模型过滤逻辑正确实现

### 任务5：智能路由器实现（40分钟）

**目标**：实现智能路由器，支持策略管理和自适应路由。

**要求**：
1. 创建`smart_router.py`文件，实现以下内容：
   - `SmartRouter`类：智能路由器
   - 内部组件：
     - `routing_strategies`: Dict[str, RoutingStrategy] - 策略字典
     - `usage_tracker`: UsageTracker - 使用情况跟踪器
   - 初始策略：
     - `cost_optimized`: CostOptimizedStrategy()
     - `performance_optimized`: PerformanceOptimizedStrategy(usage_tracker)
     - `balanced`: BalancedStrategy(usage_tracker)
     - `learning_based`: LearningBasedStrategy()
   - 实现以下方法：
     - `async def route_with_strategy()`: 使用指定策略路由
       - 检查策略是否存在
       - 调用策略的route方法
       - 返回RoutingDecision
     - `async def adaptive_route()`: 自适应路由
       - 提取请求特征
       - 根据特征选择最适合的策略
       - 使用选定的策略进行路由
     - `_extract_features()`: 提取路由特征

       - `urgency`: 基于关键词的紧急程度评分

     - `add_strategy()`: 添加自定义策略
