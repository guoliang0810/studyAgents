### 1.1 多项选择题答案

**1. 在沙箱安全机制中，以下哪个不是多层防御体系的典型层次？**
- ❌ A) 文件系统隔离层 - 是沙箱安全的重要层次
- ❌ B) 网络访问控制层 - 是沙箱安全的重要层次

**解析**: 沙箱安全机制通常采用多层防御体系，包括文件系统隔离、网络访问控制、系统调用过滤、资源限制等系统底层安全机制。用户界面安全通常由应用程序自身处理，不属于沙箱安全机制的核心层次。

**2. cgroups（控制组）在沙箱安全中主要解决什么问题？**
- ❌ A) 防止路径遍历攻击 - 由文件系统隔离和路径过滤解决
- ✅ **B) 限制进程的资源使用** - cgroups专门用于限制和监控进程组的资源使用（CPU、内存、IO等）
- ❌ C) 过滤危险系统调用 - 由seccomp机制解决
- ❌ D) 控制文件访问权限 - 由文件系统权限和访问控制列表解决
- ❌ E) 加密敏感数据 - 由加密机制解决

**解析**: cgroups（控制组）是Linux内核提供的机制，用于限制、记录和隔离进程组所使用的物理资源（CPU、内存、磁盘I/O、网络等）。在沙箱安全中，cgroups主要解决资源耗尽攻击和资源公平分配问题。

**3. seccomp-bpf机制的主要作用是什么？**
- ❌ A) 限制CPU和内存使用 - 由cgroups解决
- ❌ B) 控制网络访问权限 - 由网络命名空间和iptables解决
- ✅ **C) 过滤和限制系统调用** - seccomp-bpf允许进程声明允许使用的系统调用，阻止危险系统调用
- ❌ D) 隔离文件系统视图 - 由命名空间（尤其是mount命名空间）解决
- ❌ E) 记录安全审计日志 - 由审计子系统解决

**解析**: seccomp-bpf（安全计算模式-伯克利包过滤器）是Linux内核的安全机制，允许进程通过BPF程序过滤系统调用。在沙箱中，seccomp-bpf用于限制容器内进程只能使用安全的系统调用，防止通过系统调用进行攻击。

**4. 在SecurityLevel枚举中，"ENHANCED"安全级别的主要特点是什么？**

### 1.2 判断题答案

**1. 沙箱安全机制的目标是提供完全隔离的环境，阻止所有外部访问。**
- ✅ **错**

**解析**: 沙箱安全机制的目标是提供可控的隔离环境，而不是完全隔离。沙箱需要根据安全策略允许必要的外部访问（如网络访问、文件访问），同时阻止未经授权的访问。完全隔离会限制沙箱的实用性。

**2. cgroups只能限制内存使用，不能限制CPU使用。**
- ✅ **错**

**解析**: cgroups可以限制多种资源，包括CPU、内存、磁盘I/O、网络带宽等。cgroups通过不同的子系统（cpu、memory、blkio等）实现不同资源的限制和监控。

**3. seccomp-bpf可以基于进程的用户ID进行系统调用过滤。**
- ✅ **错**

**解析**: seccomp-bpf基于系统调用号和参数进行过滤，不能直接基于用户ID过滤。基于用户ID的访问控制通常由命名空间（用户命名空间）和capabilities机制实现。

**4. 在增强安全级别下，系统会记录详细的审计日志并进行实时威胁检测。**
- ✅ **对**

**解析**: ENHANCED安全级别提供全面防护，包括详细的审计日志记录和实时威胁检测。这是增强安全级别的核心特征，提供比标准安全更全面的安全监控。

**5. 威胁检测器会将所有包含"/etc/passwd"的路径都标记为可疑。**
- ✅ **对**

**解析**: 根据示例代码，ThreatDetector的suspicious_patterns包含"/etc/passwd"模式，任何包含该字符串的路径都会被标记为可疑，这是敏感文件访问检测的基本实现。

**6. 命名空间（namespaces）可以提供网络隔离，但不能提供文件系统隔离。**
- ✅ **错**

**解析**: 命名空间提供多种隔离能力，包括网络隔离（NET命名空间）和文件系统隔离（MNT命名空间）。MNT命名空间允许每个容器有独立的文件系统视图，是文件系统隔离的核心技术。

**7. SecurityEvent的threat_level字段用于表示安全事件的威胁程度。**
- ✅ **对**

**解析**: SecurityEvent的threat_level字段（ThreatLevel枚举）表示安全事件的威胁程度，分为INFO、LOW、MEDIUM、HIGH、CRITICAL五个级别，用于区分事件的严重程度。

**8. 沙箱安全管理器应该允许多个安全策略同时生效，提供纵深防御。**
- ✅ **对**

**解析**: 沙箱安全管理器应支持多层安全策略同时生效，实现纵深防御（Defense in Depth）。例如，同时使用文件系统隔离、资源限制、系统调用过滤等多层次防护，提高整体安全性。

**9. 资源限制配置在运行时不能动态调整。**
- ✅ **错**

**解析**: cgroups支持运行时动态调整资源限制参数。通过修改cgroup配置文件，可以在不重启进程的情况下调整CPU、内存等资源限制。

**10. 安全审计日志应该包含时间戳、事件类型、威胁级别等关键信息。**
- ✅ **对**

**解析**: 安全审计日志应包含关键信息：时间戳（事件发生时间）、事件类型（访问拒绝、资源限制等）、威胁级别（低、中、高）、详细信息（路径、用户、操作等）。这些信息对安全分析和合规性检查至关重要。

### 2.1 核心概念

**1. 请解释沙箱安全机制在多层防御体系中的重要性，并举例说明各层的防护目标。**

**参考答案**:
沙箱安全机制采用多层防御体系（Defense in Depth），通过多个安全层叠加提供纵深防御，即使单层被突破，其他层仍能提供保护。

**四层防御体系**:
1. **文件系统隔离层**
   - **防护目标**: 防止未授权文件访问、路径遍历攻击
   - **实现技术**: 命名空间（MNT命名空间）、chroot、文件系统配额
   - **示例**: 容器只能访问自己的文件系统，无法访问宿主机"/etc"目录

2. **资源限制层**
   - **防护目标**: 防止资源耗尽攻击、保证资源公平分配
   - **实现技术**: cgroups（CPU、内存、IO限制）
   - **示例**: 限制容器最多使用2个CPU核心、1GB内存

3. **系统调用过滤层**
   - **防护目标**: 阻止危险系统调用、限制攻击面
   - **实现技术**: seccomp-bpf、AppArmor、SELinux
   - **示例**: 阻止"reboot"、"mount"等危险系统调用

4. **网络安全层**
   - **防护目标**: 控制网络访问、防止网络攻击
   - **实现技术**: 网络命名空间、iptables、网络策略
   - **示例**: 容器只能访问特定端口、不能访问宿主机网络

**多层防御的重要性**:
- **冗余保护**: 单点失效不会导致整个系统沦陷
- **攻击成本**: 增加攻击者突破所有安全层的难度
- **纵深监控**: 每层都可以独立监控和检测异常
- **合规要求**: 满足安全标准对多层防护的要求

- 正确描述四层防御体系 (4分)
- 每层提供具体示例 (2分)
- 分析纵深防御优势 (1分)
- 总分: 10分

**2. 描述SecurityLevel枚举中四种安全级别（MINIMAL、STANDARD、ENHANCED、PARANOID）的区别和适用场景。**

**参考答案**:

| 安全级别 | 主要特点 | 资源限制 | 审计日志 | 威胁检测 | 适用场景 |
|---------|---------|---------|---------|---------|---------|

| ENHANCED | 全面防护，增强安全 | 严格限制 | 详细日志 | 实时检测 | 对外服务、多租户环境 |

**各级别详细区别**:

1. **MINIMAL级别**:
   - **隔离程度**: 基本命名空间隔离
   - **资源限制**: 无或非常宽松
   - **安全检测**: 仅基本威胁检测
   - **审计日志**: 无或仅错误日志
   - **性能影响**: 几乎无影响

2. **STANDARD级别**:
   - **隔离程度**: 完整命名空间隔离
   - **资源限制**: CPU、内存基本限制
   - **安全检测**: 标准威胁检测
   - **审计日志**: 基本事件记录
   - **性能影响**: 轻微影响

3. **ENHANCED级别**:
   - **隔离程度**: 增强隔离+能力限制
   - **资源限制**: 严格资源限制+配额
   - **安全检测**: 实时威胁检测+行为分析
   - **审计日志**: 详细审计+实时监控
   - **性能影响**: 中等影响

4. **PARANOID级别**:
   - **隔离程度**: 最大隔离+多重验证
   - **资源限制**: 极限限制+严格配额
   - **安全检测**: 深度检测+机器学习分析
   - **审计日志**: 完整审计+合规报告
   - **性能影响**: 显著影响

**适用场景选择指南**:
- **开发/测试**: MINIMAL或STANDARD级别，平衡安全与性能
- **一般生产**: STANDARD或ENHANCED级别，提供足够安全
- **对外服务**: ENHANCED级别，全面防护潜在攻击
- **高安全环境**: PARANOID级别，最大安全优先

**评分标准**:
- 正确描述四种安全级别的区别 (4分)

**3. 解释cgroups资源限制机制的工作原理，以及如何配置内存和CPU限制。**

**参考答案**:

**cgroups工作原理**:
1. **控制组层级结构**: cgroups通过层级结构（hierarchy）组织进程，形成树状结构
2. **子系统（subsystems）**: 不同的资源限制通过不同的子系统实现
   - cpu子系统: CPU时间分配
   - memory子系统: 内存使用限制
   - blkio子系统: 块设备IO限制
   - net_cls子系统: 网络流量控制

3. **任务绑定**: 进程（task）可以附加到特定控制组
4. **资源统计**: cgroups跟踪每个控制组的资源使用情况
5. **资源限制**: 通过配置文件设置资源使用上限

**内存限制配置**:
```bash
# 1. 创建内存控制组
sudo mkdir /sys/fs/cgroup/memory/mycontainer

# 2. 设置内存限制（1GB）
echo "1073741824" | sudo tee /sys/fs/cgroup/memory/mycontainer/memory.limit_in_bytes

# 3. 设置内存+swap限制（2GB）
echo "2147483648" | sudo tee /sys/fs/cgroup/memory/mycontainer/memory.memsw.limit_in_bytes

# 4. 将进程加入控制组
echo "PID" | sudo tee /sys/fs/cgroup/memory/mycontainer/tasks

# 5. 查看内存使用情况
cat /sys/fs/cgroup/memory/mycontainer/memory.usage_in_bytes
```

**CPU限制配置**:
```bash
# 1. 创建CPU控制组
sudo mkdir /sys/fs/cgroup/cpu/mycontainer

# 2. 设置CPU份额（相对权重，默认1024）
echo "512" | sudo tee /sys/fs/cgroup/cpu/mycontainer/cpu.shares

# 3. 设置CPU配额（CFS调度器）
# 每200ms最多使用100ms（50% CPU）
echo "100000 200000" | sudo tee /sys/fs/cgroup/cpu/mycontainer/cpu.cfs_quota_us cpu.cfs_period_us

# 4. 设置CPU亲和性（绑定到特定CPU）
echo "0-1" | sudo tee /sys/fs/cgroup/cpu/mycontainer/cpuset.cpus

# 5. 将进程加入控制组
echo "PID" | sudo tee /sys/fs/cgroup/cpu/mycontainer/tasks
```

**Python中使用cgroups**:
```python
import os
import subprocess

class CGroupManager:
    def __init__(self, name):
```

**4. 说明seccomp-bpf系统调用过滤的实现原理和安全优势。**

**参考答案**:

**seccomp-bpf实现原理**:
1. **两种模式**:
   - **严格模式（strict mode）**: 只允许read、write、exit、sigreturn四个系统调用
   - **过滤模式（filter mode）**: 使用BPF程序定义允许的系统调用规则

2. **BPF程序结构**:
   ```c
   struct sock_filter {
       __u8 code;   // 操作码
       __u8 jt;     // 真跳转偏移
       __u8 jf;     // 假跳转偏移
       __u32 k;     // 操作数
   };
   ```

3. **过滤流程**:
   - 进程发起系统调用
   - 内核检查seccomp过滤器
   - BPF程序评估系统调用
   - 根据BPF程序返回值决定允许/阻止
   - 返回值: SECCOMP_RET_ALLOW、SECCOMP_RET_KILL、SECCOMP_RET_TRAP等

4. **规则匹配**:
   - 基于系统调用号匹配
   - 基于系统调用参数匹配（最多6个参数）
   - 支持逻辑运算和比较操作

**Python中使用seccomp-bpf**:
```python
import seccomp

def create_seccomp_filter():
    """创建seccomp过滤器"""

    filter = seccomp.SyscallFilter(seccomp.ALLOW)

    filter.add_rule(seccomp.KILL, "reboot")
    filter.add_rule(seccomp.KILL, "mount")
    filter.add_rule(seccomp.KILL, "umount2")
    filter.add_rule(seccomp.KILL, "swapon")
    filter.add_rule(seccomp.KILL, "swapoff")
    
    # 加载过滤器
    filter.load()
```

**安全优势**:
1. **减少攻击面**: 限制系统调用数量，减少潜在攻击向量
2. **最小权限原则**: 进程只能使用必要的系统调用
3. **内核级防护**: 在内核层面阻止危险操作，无法绕过
4. **性能开销小**: BPF程序执行效率高，性能影响小
5. **细粒度控制**: 可基于系统调用参数进行精细控制
6. **兼容性好**: 支持所有Linux系统调用，跨架构兼容

**常见seccomp策略**:
1. **白名单策略**: 默认阻止所有，只允许特定系统调用
2. **黑名单策略**: 默认允许所有，阻止危险系统调用
3. **参数过滤**: 基于系统调用参数值进行过滤

**5. 描述Linux命名空间（namespaces）在沙箱隔离中的作用，列出至少三种命名空间类型及其隔离目标。**

**参考答案**:

**Linux命名空间作用**:
命名空间是Linux内核的隔离机制，将系统资源抽象并隔离，使不同命名空间中的进程看到不同的资源视图。在沙箱中，命名空间提供多维度的隔离，防止容器间相互影响。

**七种命名空间类型**:

1. **PID命名空间（PID namespace）**
   - **隔离目标**: 进程ID空间
   - **隔离效果**: 容器内进程只能看到自己命名空间的进程
   - **安全优势**: 防止进程枚举和信号攻击
   - **示例**: 容器内PID 1的进程在宿主机上可能是PID 1234

2. **网络命名空间（NET namespace）**
   - **隔离目标**: 网络栈（IP地址、端口、路由表、防火墙规则）
   - **隔离效果**: 每个容器有独立的网络接口和IP地址
   - **安全优势**: 网络隔离，防止网络嗅探和中间人攻击
   - **示例**: 容器内可以绑定127.0.0.1，不影响宿主机

3. **挂载命名空间（MNT namespace）**
   - **隔离目标**: 文件系统挂载点
   - **隔离效果**: 每个容器有独立的文件系统视图
   - **安全优势**: 文件系统隔离，防止文件访问攻击
   - **示例**: 容器内挂载自己的文件系统，看不到宿主机文件

4. **UTS命名空间（UTS namespace）**
   - **隔离目标**: 主机名和域名
   - **隔离效果**: 每个容器可以有独立的主机名
   - **安全优势**: 防止基于主机名的攻击
   - **示例**: 容器内主机名可以是"container1"，宿主机是"host"

5. **IPC命名空间（IPC namespace）**
   - **隔离目标**: 进程间通信资源（信号量、消息队列、共享内存）
   - **隔离效果**: 容器间IPC资源隔离
   - **安全优势**: 防止IPC攻击和资源竞争
   - **示例**: 容器内的共享内存不会与其他容器共享

6. **用户命名空间（USER namespace）**
   - **隔离目标**: 用户和组ID
   - **隔离效果**: 容器内root用户在宿主机上可能是普通用户
   - **安全优势**: 权限分离，即使容器内获得root也不影响宿主机
   - **示例**: 容器内UID 0（root）映射到宿主机UID 100000

7. **cgroup命名空间（CGROUP namespace）**
   - **隔离目标**: cgroup根目录视图
   - **隔离效果**: 容器只能看到自己的cgroup
   - **安全优势**: 防止cgroup信息泄露和攻击
   - **示例**: 容器内cgroup路径是"/"，实际是宿主机cgroup的子路径

```python
import re
from typing import List, Tuple

class PathTraversalDetector:
    """路径遍历攻击检测器"""
    
    # 路径遍历攻击模式
    TRAVERSAL_PATTERNS = [
        (r'\.\./', "Unix路径遍历"),
        (r'\.\.\\', "Windows路径遍历"),
        (r'\.\.\.', "多点目录可疑"),
        (r'//', "双斜杠攻击"),
        (r'\\\\', "双反斜杠攻击"),
        (r'%2e%2e', "URL编码路径遍历"),
        (r'%2f', "URL编码斜杠"),
    ]
    
    def detect(self, path: str) -> Tuple[bool, str]:
        """检测路径遍历攻击"""
        for pattern, attack_type in self.TRAVERSAL_PATTERNS:
            if re.search(pattern, path):
                return True, f"检测到{attack_type}: {pattern}"
        
        # 检查标准化后路径是否超出范围
        normalized = self.normalize_path(path)
        if normalized.startswith("../") or normalized.startswith("/.."):
            return True, "路径标准化后仍包含遍历组件"
            
        return False, "安全路径"
    
    def normalize_path(self, path: str) -> str:
        """标准化路径"""
        # 移除 './' 和 '../'
        parts = []
        for part in path.split('/'):
            if part == '..':
                if parts:
                    parts.pop()
            elif part and part != '.':
                parts.append(part)
        return '/'.join(parts)
```

```python
class SensitiveFileDetector:
    """敏感文件访问检测器"""
    
    # 敏感文件列表
    SENSITIVE_FILES = [
        "/etc/passwd",      # 用户账户信息
        "/etc/shadow",      # 密码哈希
        "/etc/gshadow",     # 组密码
        "/root/.ssh/authorized_keys",  # SSH授权密钥
        "/root/.bash_history",         # bash历史
        "/proc/self/environ",          # 环境变量
        "/proc/self/maps",             # 内存映射
        "/proc/self/fd",               # 文件描述符
    ]
    
    # 敏感目录模式
    SENSITIVE_PATTERNS = [
        r'/proc/\d+',      # 其他进程信息
        r'/sys/.*',        # 系统信息
        r'/dev/(?:mem|kmem|port)',  # 设备文件
    ]
    
    def detect(self, path: str) -> Tuple[bool, str]:
        """检测敏感文件访问"""
        # 精确匹配敏感文件
        for sensitive_file in self.SENSITIVE_FILES:
            if path == sensitive_file:
                return True, f"访问敏感文件: {sensitive_file}"
        
        # 模式匹配敏感文件
        for pattern in self.SENSITIVE_PATTERNS:
            if re.match(pattern, path):
                return True, f"访问敏感路径: {pattern}"
        
        # 检查路径组件
        components = path.split('/')
        dangerous_components = ['..', '.ssh', '.bash_history', 'shadow', 'passwd']
        for comp in components:
            if comp in dangerous_components:
                return True, f"路径包含敏感组件: {comp}"
                
        return False, "安全文件"
```

4. **工厂模式**: 根据配置创建安全组件实例
5. **外观模式**: 提供统一的安全接口，隐藏内部复杂性

**安全管理器实现**:
```python
from typing import Dict, List, Tuple, Optional
from dataclasses import dataclass
from enum import Enum

class SecurityLevel(Enum):
    """安全级别"""
    MINIMAL = "最小安全"
    STANDARD = "标准安全"
    ENHANCED = "增强安全"
    PARANOID = "偏执安全"

@dataclass
class SandboxSecurityConfig:
    """沙箱安全配置"""
    security_level: SecurityLevel = SecurityLevel.STANDARD
    memory_limit_mb: int = 1024
    cpu_shares: int = 512
    max_processes: int = 100
    allowed_paths: List[str] = None
    blocked_syscalls: List[str] = None
    enable_audit_log: bool = True
    enable_threat_detection: bool = True
    
    def __post_init__(self):
        if self.allowed_paths is None:
            self.allowed_paths = ["/tmp", "/home"]
        if self.blocked_syscalls is None:
            self.blocked_syscalls = ["reboot", "mount", "umount2"]

class SandboxSecurityManager:
    """沙箱安全管理器"""
    
    def __init__(self, config: SandboxSecurityConfig, sandbox_id: str = "default"):
        self.config = config
        self.sandbox_id = sandbox_id
        
        # 初始化安全组件
        self.auditor = SecurityAuditor()
        self.resource_limiter = ResourceLimiter(config)
        self.permission_controller = PermissionController(config)
        self.threat_detector = ThreatDetector(self.auditor)
        
        # 根据安全级别配置组件
        self._configure_security_level()
        
        # 记录初始化事件
        self.auditor.log_event(SecurityEvent(
            event_type=SecurityEventType.ACCESS_DENIED,
            threat_level=ThreatLevel.INFO,
            message=f"沙箱安全初始化: {config.security_level.value}",
            details={"config": asdict(config)},
            sandbox_id=sandbox_id,
        ))
    
    def _configure_security_level(self):
        """根据安全级别配置组件"""
        if self.config.security_level == SecurityLevel.MINIMAL:
            self.resource_limiter.set_relaxed_limits()
            self.threat_detector.disable_advanced_detection()
            
        elif self.config.security_level == SecurityLevel.STANDARD:
            self.resource_limiter.set_standard_limits()
            self.threat_detector.enable_standard_detection()
            
        elif self.config.security_level == SecurityLevel.ENHANCED:
            self.resource_limiter.set_strict_limits()
            self.threat_detector.enable_advanced_detection()
            self.auditor.enable_detailed_logging()
            
        elif self.config.security_level == SecurityLevel.PARANOID:
            self.resource_limiter.set_extreme_limits()
            self.threat_detector.enable_maximum_detection()
            self.auditor.enable_full_audit_trail()
    
    def check_access(self, path: str, operation: str = "read") -> Tuple[bool, str]:
        """检查访问权限（综合检查）"""
        # 1. 威胁检测
        if self.config.enable_threat_detection:
            is_suspicious = self.threat_detector.analyze_path(path, self.sandbox_id)
            if is_suspicious:
                self.auditor.log_event(SecurityEvent(
                    event_type=SecurityEventType.SUSPICIOUS_ACTIVITY,
                    threat_level=ThreatLevel.HIGH,
                    message=f"检测到可疑路径访问: {path}",
                    details={"path": path, "operation": operation},
                    sandbox_id=self.sandbox_id,
                ))
                return False, "路径被威胁检测阻止"
        
        # 2. 权限检查
        allowed, message = self.permission_controller.check_file_access(path, operation)
        if not allowed:
            self.auditor.log_event(SecurityEvent(
                event_type=SecurityEventType.ACCESS_DENIED,
                threat_level=ThreatLevel.MEDIUM,
                message=message,
                details={"path": path, "operation": operation},
                sandbox_id=self.sandbox_id,
            ))
            return False, message
        
        # 3. 资源检查
        if not self.resource_limiter.check_operation(operation):
            self.auditor.log_event(SecurityEvent(
                event_type=SecurityEventType.RESOURCE_LIMIT,
                threat_level=ThreatLevel.MEDIUM,
                message=f"操作 {operation} 超过资源限制",
                details={"operation": operation},
                sandbox_id=self.sandbox_id,
            ))
            return False, "资源限制阻止"
        
        return True, "访问允许"
    
    def allocate_resource(self, resource_type: str, amount: float) -> Tuple[bool, str]:
        """分配资源"""
        success, message = self.resource_limiter.allocate(resource_type, amount)
        
        if not success:
            self.auditor.log_event(SecurityEvent(
                event_type=SecurityEventType.RESOURCE_LIMIT,
                threat_level=ThreatLevel.MEDIUM,
                message=f"资源分配失败: {message}",
                details={"resource_type": resource_type, "amount": amount},
                sandbox_id=self.sandbox_id,
            ))
        
        return success, message
    
    def get_statistics(self) -> Dict:
        """获取安全统计"""
        return {
            "total_events": len(self.auditor.events),
            "access_denied": self.auditor.event_counts[SecurityEventType.ACCESS_DENIED],
            "resource_limits": self.auditor.event_counts[SecurityEventType.RESOURCE_LIMIT],
            "threats_detected": self.auditor.event_counts[SecurityEventType.SUSPICIOUS_ACTIVITY],
            "security_level": self.config.security_level.value,
            "sandbox_id": self.sandbox_id,
        }
    
    def generate_security_report(self) -> Dict:
        """生成安全报告"""
        analytics = SecurityAnalytics(self.auditor)
        reporter = SecurityReporter()
        
        return {
            "overview": self.get_statistics(),
            "detailed_analysis": analytics.get_statistics(),
            "compliance": reporter.generate_compliance_report(self.auditor),
            "anomalies": analytics.detect_anomalies(),
            "recommendations": reporter.get_recommendations(
                analytics.get_statistics()
            ),
        }
```

**组件协调机制**:
1. **事件流**: 安全事件在组件间传递，每个组件可以添加信息
2. **配置共享**: 通过配置对象共享安全参数
3. **状态同步**: 组件状态通过安全管理器同步
4. **错误传播**: 安全检查失败时，错误信息向上传播
5. **日志聚合**: 所有组件日志聚合到统一审计器
