## 🎯 教学目标

### 知识目标（学生将知道/理解）
1. **多级缓存架构设计原理**: 理解内存缓存、Redis缓存、持久化缓存的三级架构及其适用场景
2. **智能缓存实现机制**: 掌握基于LRU策略的内存缓存实现和基于TTL的过期管理
3. **LLM响应缓存策略**: 了解如何根据temperature参数动态调整LLM响应的缓存时间
4. **缓存键生成算法**: 理解使用MD5哈希生成唯一缓存键的原理和方法

### 技能目标（学生将能够）
1. **实现三级缓存系统**: 能够编写内存缓存、Redis缓存和持久化缓存的集成代码
2. **设计智能缓存装饰器**: 能够使用Python装饰器实现带TTL的内存缓存功能
3. **优化LLM响应缓存**: 能够根据模型参数动态调整缓存策略，提升响应速度和降低成本
4. **分析缓存性能**: 能够使用性能分析工具评估缓存命中率和响应时间改善效果

### 情感/态度目标
1. **培养性能优化意识**: 认识到缓存策略对系统性能的关键影响，养成主动优化思维
2. **建立成本效益观念**: 理解缓存策略在降低LLM API调用成本方面的重要作用
3. **增强架构设计自信**: 通过实现复杂缓存系统，提升对大型系统架构设计的信心

from typing import Optional, Any
import hashlib
import json
from datetime import datetime, timedelta
from functools import wraps

class IntelligentCache:
    """智能缓存系统"""
    
    def __init__(self, redis_client=None):
        self.memory_cache = {}
        self.redis = redis_client
        
    def _generate_key(self, func_name: str, *args, **kwargs) -> str:
        """生成缓存键"""
        # 将参数序列化为JSON字符串
        args_str = json.dumps(args, sort_keys=True)
        kwargs_str = json.dumps(kwargs, sort_keys=True)
        
        # 生成MD5哈希作为键
        content = f"{func_name}:{args_str}:{kwargs_str}"
        return hashlib.md5(content.encode()).hexdigest()
    
    def cache_memory(self, ttl_seconds: int = 300):
        """内存缓存装饰器"""
        def decorator(func):
            @wraps(func)
            async def wrapper(*args, **kwargs):
                key = self._generate_key(func.__name__, *args, **kwargs)
                
                # 检查内存缓存
                if key in self.memory_cache:
                    entry = self.memory_cache[key]
                    if datetime.now() < entry['expires']:
                        return entry['value']
                
                # 执行函数
                result = await func(*args, **kwargs)
                
                # 更新缓存
                self.memory_cache[key] = {
                    'value': result,
                    'expires': datetime.now() + timedelta(seconds=ttl_seconds)
                }
                
                # 清理过期条目
                self._clean_expired_memory()
                
                return result
            return wrapper
        return decorator
    
    def _clean_expired_memory(self):
        """清理过期内存缓存"""
        now = datetime.now()
        expired_keys = [
            key for key, entry in self.memory_cache.items()
            if entry['expires'] < now
        ]
        for key in expired_keys:
            del self.memory_cache[key]

class LLMResponseCache:
    """LLM响应缓存，考虑temperature和max_tokens"""
    
    async def get_cached_response(
        self,
        model: str,
        messages: List[Dict],
        temperature: float,
        max_tokens: int
    ) -> Optional[Dict]:
        """获取缓存的LLM响应"""
        
        # 生成缓存键（考虑所有参数）
        cache_key = self._generate_llm_key(
            model, messages, temperature, max_tokens
        )
        
        # 检查缓存
        cached = await self.redis.get(cache_key)
        if cached:
            return json.loads(cached)
        
        return None
    
    async def cache_response(
        self,
        model: str,
        messages: List[Dict],
        temperature: float,
        max_tokens: int,
        response: Dict
    ):
        """缓存LLM响应"""
        
        # 根据temperature决定缓存时间
        # temperature越低，响应越确定，缓存时间越长
        if temperature < 0.3:
            ttl = 3600 * 24  # 24小时
        elif temperature < 0.7:
            ttl = 3600  # 1小时
        else:
            ttl = 300  # 5分钟
        
        cache_key = self._generate_llm_key(
            model, messages, temperature, max_tokens
        )
        
        await self.redis.setex(
            cache_key,
            ttl,
            json.dumps(response)
        )

### 附录F：缓存策略选择指南
| 场景特征 | 推荐缓存策略 | 理由 | 注意事项 |
|----------|--------------|------|----------|
| 高频、小数据量、变化快 | 内存缓存（LRU） | 访问速度快，适合热点数据 | 注意内存限制，设置合理大小 |
| 中频、中等数据量、需要持久化 | Redis缓存（TTL） | 性能与持久化平衡，支持分布式 | 配置合理TTL，避免数据过期问题 |
| 低频、大数据量、长期有效 | 数据库缓存 | 存储成本低，查询效率可接受 | 需要索引优化，考虑查询性能 |
| LLM响应、参数敏感 | Temperature敏感缓存 | 根据确定性调整缓存时间，优化成本 | 需要仔细设计缓存键，包含所有相关参数 |
| 工具调用、结果稳定 | 工具结果缓存 | 避免重复计算，提升响应速度 | 需要考虑工具副作用和结果一致性 |
