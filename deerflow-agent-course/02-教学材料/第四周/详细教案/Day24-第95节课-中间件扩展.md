# 🎓 详细教案 - 45分钟课堂

## 📋 课程基本信息
- **课程名称**: 中间件扩展
- **授课日期**: 2024年4月17日（周三）
- **上课时间**: 上午11:00-11:45
- **授课教师**: 张老师
- **学生背景**: Python基础一般，刚学完基础语法，对AI有浓厚兴趣，已完成工具扩展机制学习
- **教室环境**: 虚拟教室，共享屏幕，10名学员在线

## 🎯 教学目标

### 知识目标（学生将知道/理解）
1. 理解可插拔中间件系统的架构设计原则
2. 掌握中间件链的执行机制和优先级管理
3. 了解中间件注册表的实现原理和自动发现机制
4. 认识企业级中间件扩展系统的设计模式和最佳实践

### 技能目标（学生将能够）
1. 实现一个功能完整的中间件基类和中间件链
2. 使用中间件注册表动态注册和发现中间件
3. 设计并实现自定义中间件，扩展系统功能
4. 在实际项目中应用中间件扩展机制，提高系统灵活性

### 情感/态度目标
1. 培养对系统解耦和模块化设计的重视
2. 增强解决复杂中间件编排问题的信心和能力
3. 激发对AOP（面向切面编程）思想的兴趣
4. 培养团队协作和代码复用意识

## 📚 教学重点与难点
- **教学重点**: 可插拔中间件系统核心组件设计、中间件链执行机制、注册表实现
- **教学难点**: 中间件优先级管理、工具调用包装、自动发现机制、性能优化
- **突破方法**: 通过实际代码演示逐步讲解，使用可视化工具展示中间件执行流程，分组讨论设计决策

## 🛠️ 教学资源准备
- **硬件**: 演示用电脑（16GB+ RAM，支持AVX指令集）
- **软件**: Python 3.12.0、VS Code、Jupyter Notebook、Git
- **账户**: GitHub账户、API密钥（可选）

- **演示材料**: PPT幻灯片、中间件扩展架构图、执行流程图
- **学生材料**: 练习手册、中间件设计模板、评估表

## 🎭 师生互动设计

### 提问策略
1. **导入提问**: "中间件和插件有什么区别？中间件在Agent系统中扮演什么角色？"
2. **引导提问**: "中间件链应该如何设计才能保证执行顺序和性能？"
3. **挑战提问**: "如果多个中间件修改同一个状态，如何保证数据一致性？"
4. **应用提问**: "在你的项目中，哪些功能适合设计为中间件？"

### 讨论活动
1. **小组讨论**: 3-4人小组，讨论不同中间件执行顺序策略的优缺点
2. **头脑风暴**: 集体创意，设计一个支持中间件依赖管理的系统
3. **案例分析**: 分析真实开源项目的中间件扩展实现
4. **代码审查**: 互相review中间件实现代码，提高代码质量

### 反馈机制
1. **即时反馈**: 课堂问答，及时纠正对中间件概念的理解偏差
2. **过程反馈**: 练习指导，帮助学生正确实现中间件基类方法
3. **成果反馈**: 作业批改，提供中间件注册表的改进建议
4. **同伴反馈**: 学生互评中间件设计，学习优秀设计模式

## 🔧 差异化教学

### 针对基础薄弱学生
1. **简化任务**: 提供完整的Middleware基类代码，只需实现before_agent方法
2. **额外支持**: 一对一辅导，讲解Python异步编程的概念
3. **资源推荐**: 提供Python异步编程的简明教程
4. **成功体验**: 设计简单的"HelloMiddleware"，快速获得成功体验

### 针对进阶学生
1. **扩展挑战**: 实现支持中间件依赖解析和冲突检测的高级注册表
2. **创新空间**: 探索基于配置文件的中间件自动编排机制
3. **领导机会**: 担任小组长，帮助其他同学理解中间件链执行流程
4. **项目实战**: 设计并实现一个小型中间件市场原型

### 针对中等水平学生
1. **渐进提升**: 从简单中间件实现到复杂中间件链逐步提升
2. **榜样学习**: 学习优秀同学设计的优雅中间件接口
3. **目标引导**: 设定明确的中间件系统设计目标
4. **反馈激励**: 及时肯定良好的架构设计决策

## 📊 评估方式

### 形成性评估（课堂内）
1. **观察评估**: 观察学生参与度、对中间件概念的理解程度
2. **提问评估**: 通过提问检验中间件链机制的理解
3. **练习评估**: 检查中间件实现完成情况和代码质量
4. **自评互评**: 学生自我评估中间件设计，互相评估实现

### 总结性评估（课堂后）
1. **作业评估**: 批改MiddlewareRegistry实现，评分反馈
2. **测验评估**: 单元测验，检验中间件扩展知识点掌握
3. **项目评估**: 项目中的中间件扩展系统设计质量
4. **综合评估**: 结合课堂表现、作业质量和项目应用综合评价

### 评估标准
- **优秀（90-100分）**: 全面掌握中间件扩展机制，能独立设计企业级中间件管理系统
- **良好（80-89分）**: 基本掌握核心概念，能实现功能完整的中间件链
- **合格（60-79分）**: 理解中间件扩展基本概念，能实现简单中间件和链
- **需改进（<60分）**: 需要重新学习中间件扩展核心概念

# 课堂练习：实现一个日志中间件

## 任务描述
创建一个LoggingMiddleware类，继承自Middleware基类，实现基本的日志记录功能。

## 要求
- [ ] 继承Middleware抽象基类，实现所有抽象方法
- [ ] 在before_agent方法中记录Agent执行开始信息
- [ ] 在after_agent方法中记录Agent执行完成信息
- [ ] 在wrap_tool_call方法中记录工具调用信息
- [ ] 通过配置支持不同的日志级别和输出目标

## 步骤指导
1. 导入Middleware基类和必要的类型注解
2. 创建LoggingMiddleware类继承Middleware
3. 实现__init__方法，接收并处理配置
4. 实现before_agent方法，记录state信息
5. 实现after_agent方法，记录response信息
6. 实现wrap_tool_call方法，记录工具调用信息

## 提示与技巧
- 使用Python的logging模块或简单的print语句
- 在before_agent和after_agent方法中返回原始参数，不要修改
- 使用super().wrap_tool_call调用父类实现
- 可以通过配置控制日志详细程度

## 检查点
- [ ] 类继承关系正确
- [ ] 抽象方法全部实现
- [ ] 日志记录功能完整
- [ ] 配置支持灵活
