# 🎓 详细教案 - 45分钟课堂

## 📋 课程基本信息
- **课程名称**: 监控与告警
- **授课日期**: 2024年4月18日（周四）
- **上课时间**: 下午12:00-12:45
- **授课教师**: 张老师
- **学生背景**: Python基础一般，刚学完基础语法，对AI有浓厚兴趣，已完成CI/CD流水线学习
- **教室环境**: 虚拟教室，共享屏幕，10名学员在线

## 🎯 教学目标

### 知识目标（学生将知道/理解）
1. 理解监控系统的核心概念和价值
2. 掌握Prometheus监控配置和告警规则编写方法
3. 了解Grafana仪表板的设计原则和最佳实践
4. 认识企业级监控系统的架构设计和优化策略

### 技能目标（学生将能够）
1. 配置Prometheus监控目标，收集应用指标数据
2. 编写Prometheus告警规则，支持多级告警和通知
3. 设计Grafana仪表板，可视化监控数据和性能指标
4. 在实际项目中应用监控系统，提高系统可观察性和故障恢复能力

### 情感/态度目标
1. 培养对系统可观察性和运维可见性的重视和兴趣
2. 增强解决复杂监控问题的信心和能力
3. 激发对SRE（站点可靠性工程）和运维自动化的热情
4. 培养数据驱动决策和持续改进的意识

## 📚 教学重点与难点
- **教学重点**: 监控系统核心概念、Prometheus配置、告警规则设计、Grafana仪表板
- **教学难点**: 指标数据模型、PromQL查询语言、告警条件优化、多数据源集成
- **突破方法**: 通过实际配置演示逐步讲解，使用可视化工具展示监控数据，分组讨论设计决策

## 🛠️ 教学资源准备
- **硬件**: 演示用电脑（16GB+ RAM）
- **软件**: Prometheus、Grafana、Docker、kubectl（可选）
- **账户**: Grafana账户（可选）、监控服务账户（可选）
- **代码**: DeerFlow 2.0代码库（提前克隆到本地）、本课示例配置
- **演示材料**: PPT幻灯片、监控系统架构图、仪表板截图
- **学生材料**: 练习手册、监控配置模板、评估表

## 🎭 师生互动设计

### 提问策略
1. **导入提问**: "监控和日志有什么区别？监控系统应该关注哪些指标？"
2. **引导提问**: "Prometheus告警规则应该如何设计才能避免误报和漏报？"
3. **挑战提问**: "如何设计监控系统支持大规模分布式应用？"
4. **应用提问**: "在你的项目中，哪些指标对业务最重要？应该如何监控？"

### 讨论活动
1. **小组讨论**: 3-4人小组，讨论不同监控策略（基于阈值 vs 基于异常检测）的优缺点
2. **头脑风暴**: 集体创意，设计一个支持多维度分析的监控仪表板
3. **案例分析**: 分析真实企业项目的监控系统实现
4. **代码审查**: 互相review监控配置，提高配置质量

### 反馈机制
1. **即时反馈**: 课堂问答，及时纠正对监控概念的理解偏差
2. **过程反馈**: 练习指导，帮助学生正确编写告警规则
3. **成果反馈**: 作业批改，提供监控系统配置的改进建议
4. **同伴反馈**: 学生互评监控设计，学习优秀设计模式

## 🔧 差异化教学

### 针对基础薄弱学生
1. **简化任务**: 提供基础的告警规则模板，只需修改阈值和条件
2. **额外支持**: 一对一辅导，讲解PromQL基本语法和概念
3. **资源推荐**: 提供Prometheus官方入门教程
4. **成功体验**: 设计简单的"高错误率"告警规则，快速获得成功体验

### 针对进阶学生
1. **扩展挑战**: 实现基于机器学习的异常检测和智能告警
2. **创新空间**: 探索多集群监控和联邦集群管理
3. **领导机会**: 担任小组长，帮助其他同学理解监控数据模型
4. **项目实战**: 设计并实现一个小型可观察性平台

### 针对中等水平学生
1. **渐进提升**: 从简单告警规则到复杂仪表板逐步提升
2. **榜样学习**: 学习优秀同学设计的优雅监控配置
3. **目标引导**: 设定明确的监控系统设计目标
4. **反馈激励**: 及时肯定良好的监控设计决策

## 📊 评估方式

### 形成性评估（课堂内）
1. **观察评估**: 观察学生参与度、对监控概念的理解程度
2. **提问评估**: 通过提问检验告警规则编写能力
3. **练习评估**: 检查告警规则完成情况和质量
4. **自评互评**: 学生自我评估监控设计，互相评估实现

### 总结性评估（课堂后）
1. **作业评估**: 批改完整监控系统配置，评分反馈
2. **测验评估**: 单元测验，检验监控系统知识点掌握
3. **项目评估**: 项目中的监控系统设计质量
4. **综合评估**: 结合课堂表现、作业质量和项目应用综合评价

### 评估标准
- **优秀（90-100分）**: 全面掌握监控系统，能独立设计企业级可观察性方案
- **良好（80-89分）**: 基本掌握核心概念，能编写优化的监控配置和告警规则
- **合格（60-79分）**: 理解监控基本概念，能编写简单告警规则
- **需改进（<60分）**: 需要重新学习监控系统核心概念

## 🚨 应急预案

### 技术故障
1. **网络中断**: 准备离线演示材料，录制监控配置讲解视频备用
2. **软件故障**: 准备在线监控环境（如Prometheus Playground）备用
3. **电力中断**: 提前通知学员，调整课程时间
4. **平台故障**: 准备备用教学平台（Zoom、腾讯会议等）

### 学生问题
1. **理解困难**: 放慢节奏，增加监控概念示例，一对一辅导
2. **设备问题**: 提供远程协助，共享屏幕指导Prometheus安装
3. **时间不足**: 调整内容优先级，先确保告警规则核心概念
4. **兴趣不足**: 增加实际应用场景，展示监控系统的强大功能

### 内容调整
1. **进度过快**: 增加告警规则练习时间，补充PromQL语法讲解
2. **进度过慢**: 精简高级特性细节，聚焦监控核心概念
3. **内容过难**: 分解复杂概念，先掌握基础指标再学习告警规则
4. **内容过易**: 增加企业级监控系统挑战，探讨性能优化

```markdown
# 课堂练习：编写一个Prometheus告警规则

## 任务描述
为DeerFlow Agent应用编写Prometheus告警规则，监控高错误率情况。

## 要求
- [ ] 定义告警名称：HighErrorRate
- [ ] 设置告警条件：5分钟内错误率超过5%
- [ ] 配置告警持续时间：持续2分钟
- [ ] 设置告警标签：severity: warning
- [ ] 配置告警注解：包含摘要和详细描述
- [ ] 使用适当的PromQL表达式

## 步骤指导
1. 创建alerts.yml文件
2. 定义告警规则组
3. 编写告警规则，包括：
   - alert: 告警名称
   - expr: PromQL表达式
   - for: 持续时间
   - labels: 标签
   - annotations: 注解
4. 测试PromQL表达式是否正确

## 提示与技巧
- 错误率计算公式：rate(http_requests_total{status="error"}[5m]) / rate(http_requests_total[5m])
- 使用> 0.05表示5%阈值
- 注解中可以使用{{ $value }}引用当前值
- 标签用于告警路由和分组

## 检查点
- [ ] PromQL表达式正确
- [ ] 阈值设置合理
- [ ] 标签和注解完整
- [ ] YAML格式正确

## 扩展挑战（可选）
- 添加高延迟告警规则
- 配置内存使用率告警
- 实现Pod重启频繁告警
- 集成通知渠道（如Email、Slack）
```
