# 🎓 详细教案 - 45分钟课堂

## 📋 课程基本信息
- **课程名称**: CI/CD流水线
- **授课日期**: 2024年4月18日（周四）
- **上课时间**: 上午11:00-11:45
- **授课教师**: 张老师
- **学生背景**: Python基础一般，刚学完基础语法，对AI有浓厚兴趣，已完成Kubernetes部署学习
- **教室环境**: 虚拟教室，共享屏幕，10名学员在线

## 🎯 教学目标

### 知识目标（学生将知道/理解）
1. 理解CI/CD的核心概念和价值
2. 掌握GitHub Actions工作流的编写方法
3. 了解自动化测试、构建、部署的流水线设计
4. 认识企业级CI/CD流水线的安全考虑和优化策略

### 技能目标（学生将能够）
1. 编写GitHub Actions工作流，支持代码检查、测试、构建和部署
2. 使用Docker构建和推送镜像到容器仓库
3. 配置自动化测试流水线，包括单元测试、集成测试和性能测试
4. 在实际项目中应用CI/CD流水线，提高开发效率和代码质量

### 情感/态度目标
1. 培养对自动化开发和持续交付的重视和兴趣
2. 增强解决复杂CI/CD流水线问题的信心和能力
3. 激发对DevOps文化和工程卓越的热情
4. 培养质量意识和团队协作精神

## 📚 教学重点与难点
- **教学重点**: CI/CD核心概念、GitHub Actions工作流设计、自动化测试策略、安全部署
- **教学难点**: 多环境部署策略、流水线优化、测试数据管理、密钥安全
- **突破方法**: 通过实际配置演示逐步讲解，使用可视化工具展示流水线流程，分组讨论设计决策

## 🛠️ 教学资源准备
- **硬件**: 演示用电脑（16GB+ RAM）
- **软件**: Git、GitHub账户、Docker、kubectl（可选）
- **账户**: GitHub账户、容器镜像仓库账户（如Docker Hub、GitHub Container Registry）
- **代码**: DeerFlow 2.0代码库（提前克隆到本地）、本课示例配置
- **演示材料**: PPT幻灯片、CI/CD流水线图、工作流配置示例
- **学生材料**: 练习手册、CI/CD配置模板、评估表

## 🎭 师生互动设计

### 提问策略
1. **导入提问**: "手动部署和自动化部署有什么区别？自动化部署有什么好处？"
2. **引导提问**: "GitHub Actions工作流应该如何设计才能支持多环境部署？"
3. **挑战提问**: "如何确保CI/CD流水线的安全性和密钥管理？"
4. **应用提问**: "在你的项目中，哪些步骤适合自动化到CI/CD流水线？"

### 讨论活动
1. **小组讨论**: 3-4人小组，讨论不同CI/CD工具（GitHub Actions vs GitLab CI vs Jenkins）的优缺点
2. **头脑风暴**: 集体创意，设计一个支持多团队协作的CI/CD流水线
3. **案例分析**: 分析真实企业项目的CI/CD流水线实现
4. **代码审查**: 互相review工作流配置，提高配置质量

### 反馈机制
1. **即时反馈**: 课堂问答，及时纠正对CI/CD概念的理解偏差
2. **过程反馈**: 练习指导，帮助学生正确编写GitHub Actions配置
3. **成果反馈**: 作业批改，提供CI/CD流水线的改进建议
4. **同伴反馈**: 学生互评流水线设计，学习优秀设计模式

## 🔧 差异化教学

### 针对基础薄弱学生
1. **简化任务**: 提供基础的GitHub Actions模板，只需修改少数配置
2. **额外支持**: 一对一辅导，讲解YAML语法和GitHub Actions基本概念
3. **资源推荐**: 提供GitHub Actions官方入门教程
4. **成功体验**: 设计简单的"Hello World"工作流，快速获得成功体验

### 针对进阶学生
1. **扩展挑战**: 实现支持多集群部署和自动回滚的CI/CD流水线
2. **创新空间**: 探索基于AI的代码审查和测试优化
3. **领导机会**: 担任小组长，帮助其他同学理解流水线设计
4. **项目实战**: 设计并实现一个小型CI/CD平台

### 针对中等水平学生
1. **渐进提升**: 从简单工作流到复杂流水线逐步提升
2. **榜样学习**: 学习优秀同学设计的优雅CI/CD配置
3. **目标引导**: 设定明确的CI/CD流水线目标
4. **反馈激励**: 及时肯定良好的流水线设计决策

## 📊 评估方式

### 形成性评估（课堂内）
1. **观察评估**: 观察学生参与度、对CI/CD概念的理解程度
2. **提问评估**: 通过提问检验工作流配置编写能力
3. **练习评估**: 检查GitHub Actions配置完成情况和质量
4. **自评互评**: 学生自我评估CI/CD设计，互相评估实现

### 总结性评估（课堂后）
1. **作业评估**: 批改完整CI/CD流水线配置，评分反馈
2. **测验评估**: 单元测验，检验CI/CD流水线知识点掌握
3. **项目评估**: 项目中的CI/CD流水线设计质量
4. **综合评估**: 结合课堂表现、作业质量和项目应用综合评价

### 评估标准
- **优秀（90-100分）**: 全面掌握CI/CD流水线，能独立设计企业级自动化部署方案
- **良好（80-89分）**: 基本掌握核心概念，能编写优化的工作流配置
- **合格（60-79分）**: 理解CI/CD基本概念，能编写简单工作流配置
- **需改进（<60分）**: 需要重新学习CI/CD流水线核心概念

## 🚨 应急预案

### 技术故障
1. **网络中断**: 准备离线演示材料，录制GitHub Actions讲解视频备用
2. **软件故障**: 准备在线CI/CD环境（如GitLab CI Sandbox）备用
3. **电力中断**: 提前通知学员，调整课程时间
4. **平台故障**: 准备备用教学平台（Zoom、腾讯会议等）

### 学生问题
1. **理解困难**: 放慢节奏，增加CI/CD概念示例，一对一辅导
2. **设备问题**: 提供远程协助，共享屏幕指导GitHub配置
3. **时间不足**: 调整内容优先级，先确保工作流核心概念
4. **兴趣不足**: 增加实际应用场景，展示CI/CD流水线的强大功能

### 内容调整
1. **进度过快**: 增加工作流练习时间，补充YAML语法讲解
2. **进度过慢**: 精简高级特性细节，聚焦CI/CD核心概念
3. **内容过难**: 分解复杂概念，先掌握基础工作流再学习复杂流水线
4. **内容过易**: 增加企业级CI/CD流水线挑战，探讨安全优化

# 课堂练习：编写一个简单的GitHub Actions工作流

## 任务描述
为DeerFlow Agent项目编写GitHub Actions工作流，支持基本的代码检查和测试。

## 要求
- [ ] 定义工作流名称和触发器（push到main分支）
- [ ] 设置Python 3.12运行环境
- [ ] 安装项目依赖
- [ ] 运行代码检查（flake8）
- [ ] 运行单元测试（pytest）
- [ ] 上传测试覆盖率报告

## 步骤指导
1. 创建.github/workflows/ci.yml文件
2. 定义name和on触发器
3. 定义jobs，至少包含test任务
4. 在test任务中设置runs-on和steps
5. 步骤1：检出代码
6. 步骤2：设置Python环境
7. 步骤3：安装依赖
8. 步骤4：运行代码检查
9. 步骤5：运行单元测试
10. 步骤6：上传覆盖率报告

## 提示与技巧
- 使用GitHub Actions市场中的现有action（如actions/checkout、actions/setup-python）
- 注意YAML缩进和格式
- 使用缓存加速依赖安装
- 测试失败时应及时通知

## 检查点
- [ ] YAML格式正确
- [ ] 触发器配置正确
- [ ] 运行环境设置正确
- [ ] 测试步骤完整

## 扩展挑战（可选）
