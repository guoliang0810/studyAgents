## 🧠 概念理解题答案

### 练习1：缓存策略类型

**答案**：

| 策略 | 工作原理 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| Cache-Aside | 应用自行管理缓存，读取时先查缓存，miss时加载数据到缓存 | 简单灵活 | 需要应用处理缓存逻辑 | 读多写少 |
| Read-Through | 缓存自动加载数据，应用只与缓存交互 | 应用代码简单 | 首次访问慢 | 读多写少 |
| Write-Through | 写操作同时更新缓存和数据库 | 数据一致性强 | 写入性能差 | 数据一致性要求高 |
| Write-Behind | 写操作先更新缓存，异步批量更新数据库 | 写入性能高 | 可能丢数据 | 写入性能要求高 |

### 练习2：缓存失效问题

**答案**：

**缓存击穿**：大量请求同时访问一个不存在的数据，导致大量请求穿透到数据库
- 解决方案：使用互斥锁或设置短TTL

**缓存穿透**：查询不存在的数据，每次都穿透到数据库
- 解决方案：布隆过滤器、空值缓存

**缓存雪崩**：大量缓存同时过期，导致数据库压力激增
- 解决方案：随机TTL、永久缓存+过期策略

**对Agent系统影响最大**：缓存击穿（LLM调用成本高，大量击穿会导致费用激增）

### 练习3：缓存装饰器

**答案**：

```python
import time
import threading
from functools import wraps
from typing import Any, Callable, Optional, Dict

class CacheEntry:
    def __init__(self, value: Any, ttl: float):
        self.value = value
        self.expire_time = time.time() + ttl
    
    def is_expired(self) -> bool:
        return time.time() > self.expire_time

class TTLCache:
    def __init__(self, max_size: int = 100, default_ttl: float = 300):
        self.max_size = max_size
        self.default_ttl = default_ttl
        self._cache: Dict[str, CacheEntry] = {}
        self._lock = threading.Lock()
    
    def get(self, key: str) -> Optional[Any]:
        with self._lock:
            entry = self._cache.get(key)
            if entry is None:
                return None
            if entry.is_expired():
                del self._cache[key]
                return None
            return entry.value
    
    def set(self, key: str, value: Any, ttl: Optional[float] = None):
        with self._lock:
            # 超过最大容量时删除最老的条目
            if len(self._cache) >= self.max_size and key not in self._cache:
                oldest_key = min(self._cache.keys(), 
                               key=lambda k: self._cache[k].expire_time)
                del self._cache[oldest_key]
            
            ttl = ttl if ttl is not None else self.default_ttl
            self._cache[key] = CacheEntry(value, ttl)
    
    def delete(self, key: str):
        with self._lock:
            self._cache.pop(key, None)
    
    def clear(self):
        with self._lock:
            self._cache.clear()
```

### 练习4：LLM响应缓存

**答案**：

```python
import hashlib
import json
from typing import Any, Dict, Optional

class LLMResponseCache:
    def __init__(self, cache: TTLCache):
        self.cache = cache
        self.hits = 0
        self.misses = 0
    
    def _generate_key(self, prompt: str, model: str, **kwargs) -> str:
        content = json.dumps({
            "prompt": prompt,
            "model": model,
            **kwargs
        }, sort_keys=True)
        return hashlib.sha256(content.encode()).hexdigest()
    
    def get(self, prompt: str, model: str, **kwargs) -> Optional[str]:
        key = self._generate_key(prompt, model, **kwargs)
        result = self.cache.get(key)
        if result:
            self.hits += 1
        else:
            self.misses += 1
        return result
    
    def set(self, prompt: str, response: str, model: str, **kwargs):
        key = self._generate_key(prompt, model, **kwargs)
        self.cache.set(key, response)
    
    def get_hit_rate(self) -> float:
        total = self.hits + self.misses
        return self.hits / total if total > 0 else 0.0
    
    def reset_stats(self):
        self.hits = 0
        self.misses = 0

# 使用示例
cache = TTLCache(max_size=1000, default_ttl=3600)
llm_cache = LLMResponseCache(cache)

# 模拟LLM调用
prompt = "解释什么是机器学习"
cached_response = llm_cache.get(prompt, "gpt-4")

if cached_response:
    print(f"缓存命中: {cached_response}")
else:
    response = "机器学习是..."
    llm_cache.set(prompt, response, "gpt-4")
    print(f"缓存未命中，已缓存新响应")

print(f"缓存命中率: {llm_cache.get_hit_rate():.2%}")
```

### 练习5：多级缓存架构设计

**答案**：

**适合缓存的数据类型**：
1. LLM响应（成本高，可重复使用）
2. 嵌入向量（计算密集）
3. 工具执行结果（幂等操作）
4. 用户会话信息

**缓存层级设计**：
- L1：进程内内存缓存（毫秒级延迟）
- L2：Redis分布式缓存（跨进程共享）
- L3：数据库持久化缓存

**缓存一致性策略**：
- 写操作：Write-Through（同步更新）
- 读操作：Cache-Aside
- 失效策略：主动失效 + TTL过期

## 📝 思考与分析题答案

### 练习6：缓存成本效益分析

**答案**：

**收益**：
1. 降低LLM调用成本（可能节省70%+）
2. 提升响应速度（从秒级到毫秒级）
3. 减少数据库压力
4. 提升系统吞吐量

**成本**：
1. 额外的内存/存储空间
2. 缓存维护复杂性
3. 数据一致性风险
4. 缓存失效问题处理

**选择标准**：
- 访问频率：访问3次以上应缓存
- 响应价值：LLM响应优先缓存
- 数据变化频率：变化频率低的数据适合缓存
- 一致性要求：对一致性要求高的数据不缓存
