### LangGraph实战演示

**张老师**："让我们看一个实际的LangGraph状态定义。这是DeerFlow中的ThreadState："


**小王**："这个ThreadState看起来好复杂，有很多字段..."

**张老师**："别担心，我们一个个来解释。最重要的几个字段是：
1. `messages`：对话历史
2. `next`：下一步要执行的节点
3. `artifacts`：生成的文件或结果"

### 状态流转演示

**张老师**："让我们看状态如何流转。这是一个简化的状态流转示例："

```python
# 简化的状态流转
class SimpleAgentState:
    def __init__(self):
        self.messages = []
        self.next = "start"
    
    def process(self, user_input):
        if self.next == "start":
            self.messages.append(("user", user_input))
            self.next = "agent_thinking"
            return "收到用户输入，开始思考..."
        elif self.next == "agent_thinking":
            self.messages.append(("assistant", "思考中..."))
            self.next = "agent_response"
            return "思考完成，准备回复..."
        # ...更多状态

# 使用示例
agent_state = SimpleAgentState()
print(agent_state.process("你好"))
print(f"当前状态: {agent_state.next}")
```

**小王**："我明白了！状态机就是定义Agent在不同情况下的行为逻辑。"

**张老师**："完全正确！LangGraph让这个状态管理变得非常简单和强大。"

### 工具调用概念

**小王**："用过，比如联网搜索、计算器那些。"

**张老师**："非常好！工具调用就是让AI能够使用外部工具，就像给AI装上'手'和'脚'。"

### 工具定义示例

**张老师**："让我们看一个DeerFlow中的工具定义。这是tools目录下的示例："

```python
# 查看tools目录结构
import os

tools_dir = "/home/guoliang/code/deer-flow/backend/packages/harness/deerflow/tools"
if os.path.exists(tools_dir):
    print("Tools目录内容:")
    for item in os.listdir(tools_dir):
        if item.endswith('.py') and not item.startswith('_'):
            print(f"  - {item}")
else:
    print("Tools目录不存在，使用示例说明")
    
# 工具定义示例
print("\n工具定义示例:")
print('''
from langchain.tools import tool

@tool
def calculator(expression: str) -> str:
    """计算数学表达式，支持加减乘除和括号"""
    try:
        result = eval(expression)
        return f"{expression} = {result}"
    except Exception as e:
        return f"计算错误: {e}"
''')
```

**小王**："这个@tool装饰器是做什么的？"

**张老师**："这是LangChain的工具装饰器，它会自动：
1. 生成工具描述供LLM理解
2. 处理参数验证
3. 集成到Agent工具集中"

### 工具调用流程

**张老师**："让我们看工具调用的完整流程："

```python
# 工具调用流程示例
print("""
工具调用流程：

1. 用户输入 -> Agent
   "请计算(3+5)*2"

2. Agent分析 -> 需要工具
   "用户需要计算，应该调用calculator工具"

3. 生成工具调用
   {
     "tool": "calculator",
     "tool_input": {"expression": "(3+5)*2"}
   }

4. 执行工具 -> 获取结果
   "(3+5)*2 = 16"

5. 结果返回给用户
   "计算结果为16"
""")
```

### 实际工具实现

**张老师**："现在让我们看一个DeerFlow中的实际工具实现。这是sandbox工具的一部分："

```python
# 查看sandbox工具
sandbox_dir = "/home/guoliang/code/deer-flow/backend/packages/harness/deerflow/sandbox"

    for item in os.listdir(sandbox_dir):

print('''
class SandboxTool:
    """沙箱执行工具"""
    
    def __init__(self):
        self.name = "sandbox"
        self.description = "在安全沙箱中执行代码"
        
    def run(self, code: str, language: str = "python") -> str:
        """执行代码并返回结果"""
        # 实际实现会创建沙箱环境
```

3. 隔离文件访问

## 🏫 第4节：DeerFlow架构总览（12:00-12:45）

### 四层架构介绍

**张老师**："最后我们来总览DeerFlow的四层架构。小王，还记得我们早上说的AI Agent助手吗？"

**小王**："记得，能订餐、查天气那个。"

**张老师**："对！DeerFlow把这个助手分成了四层，就像大楼的楼层：

1. **一楼：Lead Agent（领导Agent）**
   - 负责决策和协调
   - 类似项目经理

2. **二楼：Middleware Chain（中间件链）**
   - 处理消息和状态
   - 类似秘书团队

3. **三楼：Tool System（工具系统）**
   - 执行具体任务
   - 类似专业工程师

4. **地下室：Subagents（子代理）**
   - 专门处理复杂任务
   - 类似外包团队"

### 架构图展示

**张老师**："让我们看实际的架构图："

```ascii
DeerFlow四层架构：

┌─────────────────────────────────┐
│        Lead Agent (领导层)       │
│  • 决策：做什么、用哪个工具       │
│  • 协调：管理整个执行流程         │
│  • 监控：跟踪任务进度和状态       │
└─────────────────────────────────┘
              │
┌─────────────────────────────────┐
│    Middleware Chain (中间件链)   │
│  • 消息处理：格式化、验证、记录    │
│  • 状态管理：保存、恢复、同步      │
│  • 安全检查：输入验证、权限控制    │
└─────────────────────────────────┘
              │
┌─────────────────────────────────┐
│      Tool System (工具系统)      │
│  • 计算工具：数学计算、数据分析    │
│  • 网络工具：搜索、API调用        │
│  • 文件工具：读写文件、处理图片    │
└─────────────────────────────────┘
              │
┌─────────────────────────────────┐
│       Subagents (子代理系统)     │
│  • 专家代理：专门领域深度处理      │
│  • 并行代理：同时处理多个任务      │
│  • 长期代理：运行长时间任务        │
└─────────────────────────────────┘
```
